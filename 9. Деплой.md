## Как обновить деплой (основной способ)
1. Внести изменения в `site/src` и т.д.
2. Из папки `site/`:
   ```
   npx vercel --prod --yes
   ```
   Vercel CLI грузит файлы с диска напрямую, поэтому реальные фото деплоятся без ограничений на размер.
3. Проверить, что адреса отвечают кодом 200 и открываются клиентские маршруты (например `/car/toyota-camry`).

Vercel CLI авторизован под аккаунтом владельца (проверено 19.09) и привязан к проекту (папка `site/.vercel/`, локальная привязка). Если CLI пишет «Not authorized» (так было дважды 16.09), нужно заново пройти вход: `npx vercel login` и подтвердить код на странице Vercel, затем повторить деплой.

Vercel MCP (`deploy_to_vercel`) годится только для правок кода без фото: он требует вставлять содержимое всех файлов прямо в вызов, поэтому реальные фото им не передать.

## Что настроено
- `site/vercel.json`: rewrite всех путей на `/index.html` (иначе прямые ссылки `/car/:slug` дают 404) и кэш-заголовки для `/cars/*`.
- Deployment Protection (Vercel Authentication) отключена вручную в дашборде: сайт публичный.
- Framework `vite`, команда сборки `npm run build`, выходная папка `dist`.
- Локальная папка `site/dist` может быть старой (сборка на Vercel идёт заново из исходников). Источником правды считать деплой, а не локальный `dist`.

## Секреты и окружение
- В `site/.env.local` лежит только служебный токен, созданный Vercel CLI (`VERCEL_OIDC_TOKEN`). Файл закрыт правилом `.env*` в `site/.gitignore`. Проект пока не в git.
- Когда будет подключаться Telegram-бот: токен бота нельзя класть в переменные с префиксом `VITE_`, они попадают в публичный код сайта. Отправку заявок делать через серверную функцию Vercel, а токен хранить в переменных окружения Vercel.

## Архив: как пришли к рабочему способу деплоя (для истории)
1. **Личный токен Vercel** (`vck_...`) оказался токеном с ограниченными правами (`"limited": true`): читал профиль и список проектов, но CLI не мог загрузить список команд, а `POST /v13/deployments` вернул `403`. Для деплоя не годился. Самодельный скрипт `deploy.mjs` (деплой через REST API) удалён как мёртвый файл.
2. **Vercel MCP** (`claude mcp add --transport http vercel https://mcp.vercel.com`): авторизация через браузер сработала, но первый деплой пришлось делать без реальных фото (SVG-заглушки), потому что фото в base64 не помещаются в вызов инструмента.
3. **Vercel CLI**, авторизованный через браузер (`vercel login`, device-code) и связанный с проектом (`vercel link --project car-rental-landing`). Это рабочее решение, им пользуются сейчас.
