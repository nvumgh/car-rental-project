## Как всё прошло: хронология работы и проблем

### 1. Сборка сайта
Собрали React + Vite + Tailwind v4 + Framer Motion + React Router на структуре из [6. Задачник](6.%20Задачник.md): главная страница (hero, каталог с фильтрами, блок преимуществ, отзывы, FAQ), страница модели (hero, галерея, характеристики, калькулятор цены, отзывы по модели, форма бронирования), RU/EN-переключатель языка. Проблем на этом этапе не было — стандартная сборка по уже готовому ТЗ и брифу дизайнера.

### 2. Деплой — самая долгая часть (см. подробности в [9. Деплой](9.%20Деплой.md))
Три подхода, прежде чем получилось:
1. **Личный токен Vercel от пользователя** — оказался токеном с ограниченными правами (`"limited": true`), годным только для чтения, не для деплоя.
2. **Vercel MCP напрямую (`deploy_to_vercel`)** — авторизация через браузер сработала, но у инструмента есть жёсткое ограничение: всё содержимое файлов (включая фото в base64) нужно вставлять прямо в вызов инструмента. Реальные фото машин физически не помещаются — это сотни тысяч токенов на одну картинку. Первый деплой пришлось делать вообще без реальных фото (SVG-заглушки с названием модели), что пользователя не устроило.
3. **Vercel CLI, авторизованный через браузер (device-code) и привязанный к тому же проекту** — решение. CLI грузит файлы с диска напрямую, без ограничений на размер. Все дальнейшие деплои идут через `vercel --prod` из `site/`.

**Результат:** стабильный, воспроизводимый процесс деплоя за одну команду, реальные фото всех 6 моделей на проде.

### 3. Полный аудит сайта (10 параллельных агентов + Playwright)
По запросу «протестируй весь сайт» запустили 10 параллельных агентов (навигация, форма/цена, i18n, данные машин, доступность, производительность, SEO, сборка/линт, вёрстка) плюс отдельного агента с настоящим headless-браузером, который кликал и скроллил сайт как пользователь. Нашли и почти всё исправили — **20 пунктов**, из них 17 закрыто, 3 сознательно отложено как низкий приоритет для демо. Полная таблица — в [8. Тестирование](8.%20Тестирование.md).

Главные находки: кнопки навигации в шапке не работали на странице модели (ссылки на `#catalog` существовали только на главной), фото на мобильном обрезалось почти до неба, форма бронирования принимала дату окончания раньше даты начала.

### 4. Реальные баги, которые пропустил автоматический аудит
После деплоя пользователь на реальном iPhone нашёл то, что headless-браузер (Chromium/WebKit) физически не мог воспроизвести:
- **Поля даты «С»/«По» вылезали за край экрана** — три раунда попыток (раскладка в один столбец → `min-w-0` + равные колонки рядом) не помогли, потому что причина не в CSS: у нативного `<input type="date">` в iOS Safari есть свой минимальный размер на уровне ОС, который не сжимается никакими стилями и на некоторых устройствах шире, чем контейнер целиком. Решение — заменить `type="date"` на обычное текстовое поле с ручным вводом и своей валидацией дат.
- Этот урок (и ещё несколько похожих) записан в новый скилл `~/.claude/skills/site-qa-checklist/SKILL.md`, чтобы в будущих проектах такие вещи проверялись сразу, а не через 3 захода.

### 5. Редизайн hero по обратной связи
Несколько раундов правок фото-блока на главной и странице модели:
1. Исходный вариант — фото на весь экран с текстом поверх (как в оригинальном дизайне).
2. Пользователь: на мобильном машины не видно, текст перекрывает фото → переделали на «фото сверху отдельным блоком, текст под ним».
3. Пользователь: пропало ощущение «hero» → добавили тёмный градиент внизу фото, из которого «выныривает» текст; несколько итераций по высоте и интенсивности градиента (выше/темнее/светлее — по факту оказалось, что тёмный вариант скрывал машину, откатили к более светлому).
4. Пользователь: на десктопе стало хуже, чем было → вернули оригинальный полноэкранный вариант **только для десктопа**, мобильная версия осталась в новом, более аккуратном виде (сайт сейчас рендерит два структурно разных блока под разные брейкпоинты, а не один на общих классах).

### 6. Точечная полировка (после того как каркас стал стабильным)
- Стрелки листания фото в галерее (сделаны неактивными, пока фото одно; символы `‹ ›` заменены на SVG — текстовые глиффы были визуально не по центру круга).
- Убрана опора парковки, случайно попавшая в кадр Lamborghini рядом со стрелкой (лёгкий зум фото).
- Иконки в блоке характеристик (места, багажник, трансмиссия, топливо) — с уточнением по обратной связи (иконка мест и трансмиссии заменена на более понятную).
- Год выпуска добавлен в данные каждой машины и выведен бейджем на карточке каталога.
- Отступ после клика «Смотреть каталог» — кнопки фильтра сначала прятались под шапкой (добавили точный `scroll-margin-top`, измеряемый реальной высотой шапки через JS), затем подрезали лишний воздух сверху по вкусу пользователя.
- Фавикон и заголовок вкладки — заменены с шаблонных (случайная фиолетовая иконка, «Демо: аренда авто в Дубае») на брендовые («RENTX — аренда авто в Дубае», тёмный кружок с золотым кольцом и буквой R).

### 7. Правки через Remote Control (15–16.09)
Вы писали в Telegram, Claude Code на Mac вносил правки и деплоил (`npx vercel --prod`). В эту ночь дважды слетала авторизация Vercel CLI («Not authorized»), её обновляли через device-code.
1. **Шрифты цен:** выровнены размер и начертание (аренда, депозит, итог); подпись «К оплате при получении» приведена к цвету остальных.
2. **Ввод дат:** сначала всё вписывалось подряд, затем сделали маску дд.мм.гггг (точки сами), ограничили день 1–31, месяц 1–12, год 2026–2028. Прошедшая дата тихо заменяется на сегодняшнюю (без предупреждения, по вашей просьбе). Исправили backspace, который «упирался» в автоматическую точку. При тарифе «Месяц» поле «По» считается само (начало + 30 дней).
3. **Итоговая сумма:** вы заметили, что при любом числе дней стоит одна цена. Теперь суточный тариф = цена за сутки × число дней + депозит, с расшифровкой; месячный — фиксированная цена.
4. **Месячные цены:** проверили и выяснили, что они были подобраны «на глаз» (скидка 40–47% от сутки × 30), а ориентир рынка из разведки — до 30% (Renty.ae). Пересчитали на скидку 30%. Суточные цены не тронули: они опираются на диапазоны из разведки.
5. **Переключатель «сутки/месяц»** в блоке цены и в форме бронирования теперь синхронизирован.

Бот сам в браузере эти правки не проверял (нет доступа к Chrome). 19.09 вы проверили их вручную (правки 16.09, переключатель RU/EN, сценарий бронирования до экрана подтверждения): всё в порядке.

## Что осталось не сделано (сознательно, не по забывчивости)
Актуальный список — в [6. Задачник](6.%20Задачник.md), раздел «Отложенные задачи», плюс из аудита ([8. Тестирование](8.%20Тестирование.md), пункты 18–20):
- **Telegram-бот и реальная отправка заявок** (Фаза 4 Задачника) — форма показывает «успех», но никуда не отправляет; нужен токен бота от пользователя.
- **SEO**: мета-описание, OG-теги, robots.txt, canonical — не критично для демо на `.vercel.app`, актуально при переезде на боевой домен.
- **Оптимизация фото**: нет `srcset`/уменьшенных превью — оригиналы (100–436 КБ) отдаются даже в маленькие карточки каталога.
- **RU/EN-вёрстка вплотную**: пара строк (например, «Средний класс») заметно длиннее английского аналога — риск переноса в узких плашках, не проверено вживую на всех экранах.
- **Название компании, логотип, фирменный стиль** — сейчас «RENTX» и фавикон-заглушка временные, не результат дизайн-работы.
- **Реальная фотосъёмка автопарка** — все фото сейчас стоковые/сгенерированные, не привязаны к реальным машинам. Вторые фото машин (добавлены 19.09) — копии первых, нужны только чтобы проверить листание галереи.
- Онлайн-оплата, юридическое оформление, помесячная аренда как бизнес-модель — вне рамок демо, см. Задачник.

## Критерии готовности к запуску (go/no-go)
Для **демо-показа** (текущая цель) — готово:
- [x] Сайт открывается по публичной ссылке без пароля
- [x] Все ключевые сценарии проходятся руками (каталог → фильтр → карточка → модель → калькулятор → форма)
- [x] Нет критических визуальных багов на мобильном и десктопе
- [x] RU/EN переключаются полностью

Для **боевого запуска** (реальный бизнес) — не готово, нужно отдельно:
- [ ] Реальный Telegram-бот вместо заглушки
- [ ] Свой домен вместо `*.vercel.app`
- [ ] Юридические реквизиты, реальный автопарк, лицензии
- [ ] SEO-базовая гигиена (мета-теги, sitemap)

## План на случай проблем (rollback)

## Метрики успеха запуска
Для демо-этапа метрика одна — **согласование дизайна и функциональности с пользователем перед боевым запуском**. Количественные метрики (конверсия, трафик) станут актуальны после подключения реального Telegram-бота, домена и первого публичного анонса.
